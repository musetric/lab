# Engine bench

Stands that measure the audio-engine questions of
[musetric/musetric#1201](https://github.com/musetric/musetric/issues/1201):
paged AAC and FLAC decoding, time-stretch modes, the cost of a render quantum
and a worker-to-worklet page pool, also on an Android phone over adb. Every
input is synthetic and generated by the stand; nothing generated is committed
(`.gitignore`).

| Stand | What it measures |
| --- | --- |
| [aac_pages](aac_pages/readme.md) | page decode of the host's AAC and FLAC in browsers against the whole decode: bit-exactness, pre-roll, cost, memory |
| [stretch_modes](stretch_modes/readme.md) | signalsmith-stretch with a constant seek against streaming: cost per quantum and click-offset accuracy |
| [worklet_stepper](worklet_stepper/readme.md) | Musetric's real worklet runtime stepped offline: allocation, time per quantum, loop-wrap renders |
| [page_pool_spike](page_pool_spike/readme.md) | browser spike of a decoder worker feeding an AudioWorklet page pool: correctness, seek latency, underruns, memory |
| [flacpage](flacpage/readme.md) | host side: the cost of a FLAC page decode with symphonia |
| [ios](ios/readme.md) | an HTTPS server for a phone on the LAN and a page that reports what the browser has |
| [android](android/readme.md) | the other stands driven over adb on a phone's Chrome or an installed app's WebView, with platform probes and the app's memory |

Common needs: Node 24 or newer, `npm ci` in a stand, and for the browser
stands Playwright with Microsoft Edge (`PLAYWRIGHT_BROWSERS_PATH` may point to
a shared browser cache). The stands that encode audio need the host encoder:
a musetric checkout in `MUSETRIC_ROOT`, or a built `media` example binary in
`MEDIA_BIN`; [shared/encode.mjs](shared/encode.mjs) calls it
(`cargo run --locked -p musetric-media --example media -- fmp4 ...` from
`packages/server` of the checkout). Memory sampling of browser processes uses
PowerShell and therefore runs on Windows only.

An openly licensed track may be used as an optional input where a stand says
so; it is never committed.

## Running on an iPhone from a Mac

Safari is the only engine on iOS, in every browser and in the app's WKWebView,
so desktop numbers say nothing about it. Setup:

1. iPhone: Settings, Safari, Advanced, turn on Web Inspector (and Remote
   Automation if a driver is wanted). Mac: Safari, Settings, Advanced, show
   features for web developers; the connected, trusted iPhone then appears in
   the Develop menu.
2. Serve the pages over HTTPS on the LAN with a self-signed certificate (a
   secure context is needed for WebCodecs and AudioWorklet):
   ```sh
   mkdir -p ios/certs && cd ios/certs
   openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 7 -keyout key.pem -out cert.pem -subj "/CN=lab" -addext "subjectAltName=IP:<mac-lan-ip>"
   cd .. && node server.mjs <stand-folder> 8443
   ```
   Open `https://<mac-lan-ip>:8443/web/index.html` on the phone after
   installing and trusting `cert.pem` (Settings, General, About, Certificate
   Trust Settings). The alternative is `http://localhost` on the Mac, inspected
   in the iOS Simulator; that is not a device measurement. Pages can post
   results to `/report`, which lands in `ios/reports.jsonl`.
3. Drive a page from the Web Inspector console of the phone: the stands expose
   `window.callWorker` (aac_pages) and `window.T` (page_pool_spike).
4. The app: a debug build of the Musetric iOS app with an inspectable WKWebView
   (`isInspectable = true`) shows up in the same Develop menu; run the checks
   below there, not only in Safari.
5. Memory: the WebContent process of the page is what iOS kills, not the app.
   Measure it with Instruments (Allocations, VM Tracker) attached to that
   process, or with `footprint -p <pid>` on the Mac for the Simulator; on a
   device use the Develop menu timelines and the jetsam events of the device
   log.

What to run on iOS:

- `SharedArrayBuffer` and `crossOriginIsolated` in the app WebView, and whether
  `AudioDecoder` (AAC `mp4a.40.2`, FLAC with STREAMINFO as description) and
  `AudioWorkletNode` exist ([ios](ios/readme.md)).
- The AAC and FLAC page comparator of aac_pages with the priming check: pre-roll
  P of 0, 1, 2 and 3 against the whole decode.
- The quantum cost of 1 and 3 stretchers (the logic of stretch_modes and
  worklet_stepper inside a real AudioWorklet).
- The page-pool spike: seek latency, underruns, and memory against the 2048 MiB
  limit.
- `resume()` of the AudioContext after the app was in the background, and the
  position after it.
